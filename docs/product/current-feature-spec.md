# 현재 브랜치 기준 프로덕트 피처 명세 (HEAD)

이 문서는 **현재 브랜치(HEAD)** 에서 실제 제공되는 피처 계약을 단일 문서로 고정합니다.
`main` 기준 원본 계약은 `docs/product/past/main-feature-baseline.md`에 보관하고, 본 문서는 현재 브랜치 운영 기준으로 사용합니다.
`docs/product/past/*` 문서는 이력/비교 기록이며, 현재 운영 계약의 source-of-truth는 본 문서입니다.

기준 브랜치: `develop@e9084df`  
프로덕트 버전: `2026.02.18+e9084df`  
적용 범위: `FiveGuyes/FiveGuyes/Sources/**`

작성 기준:
- 기본 계약: `docs/product/past/main-feature-baseline.md`
- 확정 오버라이드: `docs/product/past/current-diff-from-main.md`의 `최종 확정 결과 (2026-02-17)`

명세 작성 형식:
- `Given`: 기능 시작 전 사전 상태와 입력
- `When`: 사용자의 행동 또는 시스템 트리거
- `Then`: 화면/데이터/부작용 결과
- `엣지/오류 처리`: 경계값, 실패, 예외 처리 계약
- `관찰 가능 기준`: 테스트 또는 수동 검증 포인트

## F-01 앱 시작 및 전역 네비게이션

기능 목적:
- 앱 기동 시 데이터 저장소와 전역 라우팅을 초기화해 홈을 루트 화면으로 제공합니다.

Given:
- 앱이 콜드 스타트됩니다.
- SwiftData `ModelContainer` 초기화가 가능한 환경입니다.

When:
- `FiveGuyesApp`가 실행되고 `NavigationRootView`가 생성됩니다.

Then:
- 앱은 `ModelContainer`를 생성해 환경에 주입합니다.
- 루트 라우팅은 `NavigationCoordinator`의 `paths` 상태로 통제됩니다.
- 초기 화면은 홈(`.mainHome`)으로 렌더링됩니다.
- 앱 델리게이트에서 Firebase 초기화와 ATT 요청을 수행합니다.

엣지/오류 처리:
- `ModelContainer` 생성 실패는 앱 기동 실패로 처리됩니다.

관찰 가능 기준:
- 앱 재실행 시 홈 루트 진입 여부.
- `NavigationCoordinator` 기반 push/pop 동작 정상 여부.

## F-02 홈 대시보드

기능 목적:
- 읽는 책/완독 책 상태에 맞는 홈 요약과 주요 액션(기록, 등록, 삭제, 알림, 캘린더)을 제공합니다.

Given:
- 읽는 책 목록과 완독 책 목록이 조회 가능합니다.

When:
- 홈 화면이 나타나고 사용자가 책 카드/메뉴/버튼을 조작합니다.

Then:
- 읽는 책이 있으면 캐러셀과 점 인디케이터를 보여줍니다.
- 읽는 책이 없고 완독 책이 있으면 "완독 후 빈 상태" 메시지를 보여줍니다.
- 둘 다 없으면 "초기 빈 상태" 메시지를 보여줍니다.
- `selectedBookIndex`와 `activeBookID`를 동기화해 현재 선택 책을 일관되게 유지합니다.
- 홈 진입 시 읽는 책에 대해 재분배를 시도하고, 목표일 초과는 미완독 종료 플로우로 이동시킵니다.
- 홈 진입 직후 첫 번째 읽는 책 기준으로 알림 재설정을 시도합니다.

엣지/오류 처리:
- 읽는 책이 없는 상태에서는 전체 캘린더 버튼을 비활성화합니다.
- 책 삭제 후 선택 인덱스가 범위를 벗어나지 않도록 보정합니다.

관찰 가능 기준:
- 읽는 책 유/무, 완독 책 유/무 조합별 홈 상태 전환.
- 홈 진입 후 재분배에 따른 미완독 종료 화면 분기.

## F-03 책 검색 및 선택

기능 목적:
- 알라딘 API 검색 결과에서 책을 선택하고 총 페이지를 조회해 등록 흐름 입력값을 채웁니다.

Given:
- 사용자가 검색어를 입력할 수 있습니다.
- 앱 번들의 `API_KEY`는 환경에 따라 설정/미설정 상태일 수 있습니다.

When:
- 검색 실행 후 특정 책을 선택하고 "완료"를 누릅니다.

Then:
- 검색 결과 목록을 표시합니다.
- 선택한 책의 ISBN으로 총 페이지를 조회합니다.
- 조회된 페이지 수를 등록 입력(`targetEndPage`) 기본값으로 설정합니다.
- 선택한 책 정보를 등록 입력 모델에 저장하고 다음 단계로 이동합니다.

엣지/오류 처리:
- `API_KEY`가 없거나 미치환 placeholder(`$(API_KEY)`)이면 검색 호출 시 `BookSearchNetworkError.missingAPIKey`로 실패 처리되고, 검색 화면 Alert로 설정 누락을 안내합니다(앱 런치는 유지).
- 검색/상세 조회 URL은 `URLComponents`로 구성해 쿼리 인코딩을 보장합니다.
- HTTP 응답이 2xx가 아니면 명시적 네트워크 오류로 처리합니다.
- 검색/상세 조회 실패 시 오류 로그를 남기고 총 페이지는 `0`으로 처리합니다.
- 책 미선택 상태에서는 완료 버튼을 비활성화합니다.

관찰 가능 기준:
- 검색 성공/실패 시 UI 상태 변화.
- 선택 후 페이지 입력 단계 진입과 종료 페이지 자동 채움.

## F-04 완독 목표 설정 마법사

기능 목적:
- `검색 -> 페이지 -> 기간 -> 쉬는날 -> 완료` 순서로 책 등록 입력을 단계별로 수집합니다.

Given:
- 사용자가 등록 흐름에 진입했습니다.

When:
- 단계 이동(다음/뒤로)을 반복합니다.

Then:
- 단계 상태는 `BookSettingPageModel`이 관리합니다.
- 입력 상태는 `BookSettingInputModel`이 관리합니다.
- 진행바로 현재 단계를 표시합니다.
- 뒤로 이동 시 현재 단계에서 수집한 입력만 초기화합니다.

엣지/오류 처리:
- 단계 외 입력은 유지해 불필요한 재입력을 줄입니다.

관찰 가능 기준:
- 단계 왕복 시 입력 유지/초기화 범위 확인.
- 진행바와 실제 단계 일치 확인.

## F-05 기간/쉬는날 선택

기능 목적:
- 시작일/종료일과 쉬는날을 설정하고 예상 일일 분량을 제공합니다.

Given:
- 시작일/종료일 선택 UI와 쉬는날 토글 UI가 제공됩니다.

When:
- 사용자가 기간 선택 후 확정 모드에서 쉬는날을 선택/해제합니다.

Then:
- 선택 기간에 대한 예상 일일 페이지를 실시간 표시합니다.
- 시작일/종료일은 쉬는날로 지정되지 않습니다.
- 기간 변경 시 범위를 벗어난 기존 쉬는날을 제거합니다.

엣지/오류 처리:
- 과거 날짜는 선택할 수 없습니다.
- 날짜 비교는 `Calendar.app` 기준 정규화 날짜를 사용합니다.
- `Calendar.app`은 현재 기기 time zone을 사용하며, 04:00 경계를 기준으로 날짜를 해석합니다.
- 설정일(start/end/non-reading)은 저장 시 `ReadingDateKey(yyyy-MM-dd)`를 source-of-truth로 유지하며, `Date`는 호환용으로만 사용합니다.

관찰 가능 기준:
- 기간 재선택 시 쉬는날 정리 여부.
- 시작/종료일 쉬는날 선택 방지 동작.

## F-06 등록 완료 및 책 생성

기능 목적:
- 최종 확인 후 실제 책 데이터를 저장하고 초기 스케줄/알림을 생성합니다.

Given:
- 책 메타데이터, 페이지 범위, 기간, 쉬는날 입력이 완료되었습니다.

When:
- 사용자가 완료(등록) 액션을 실행합니다.

Then:
- 초기 진행 페이지는 `startPage - 1` 기준으로 시작합니다.
- 초기 스케줄은 종료일/쉬는날/페이지 범위를 반영해 계산됩니다.
- 책이 저장되고 첫날부터 동작하도록 알림을 설정합니다.

엣지/오류 처리:
- 저장 실패 시 오류 로그를 남기고 홈 전환을 수행하지 않습니다.

관찰 가능 기준:
- 등록 직후 읽는 책 목록 반영 여부.
- 등록 직후 알림 요청 생성 여부.

## F-07 일일 독서 기록 입력

기능 목적:
- 누적 읽은 페이지를 기록하고 필요 시 남은 일정을 재분배합니다.

Given:
- 읽는 책이 존재하고 사용자가 오늘까지 누적 페이지를 입력합니다.

When:
- 기록 저장 액션을 실행합니다.

Then:
- 결과를 일반 기록/완독/종료일 연장/초과입력으로 분기합니다.
- 목표와 실제가 다르면 미래 목표를 재계산합니다.
- 중간 날짜에 목표 종료 페이지에 도달하면 완독으로 분기하고, 이후 미래 날짜 목표는 제거합니다.
- 시작일 이전 날짜에 기록해도 해당 날짜의 기록은 저장됩니다.
- 시작일 이전 기록으로 재계산이 필요하면, 시작일 이전 자동 스케줄은 생성하지 않고 시작일부터 재분배합니다.
- 기록 후 다음 알림이 최신 상태를 반영하도록 재설정합니다.
- 기록 날짜(`todayProvider.today()`)는 현재 기기 time zone + 04:00 경계 기준으로 해석됩니다.

엣지/오류 처리:
- 목표 종료 페이지 초과 입력 시 경고 확인을 노출합니다.
- 마지막 날 미달이면 종료일을 하루 연장 후 재분배합니다.
- 제외일에 기록해서 완독한 경우에도 제외일을 해제하고 완독 분기를 적용합니다.
- 시작일 이전 기록에서 남은 유효 독서일이 0일이면 `ScheduleCalculationError.calculationFailed`를 전파합니다.

관찰 가능 기준:
- 결과 분기별 화면 이동/메시지.
- 기록 이후 미래 날짜 목표 변경 확인.
- 시작일 이전 날짜 기록 시, 시작일 이전 자동 스케줄이 생성되지 않고 시작일부터 목표가 재분배되는지 확인.

## F-08 완독 축하 요약

기능 목적:
- 완독 직후 기간/일수/일일 평균 읽기량 요약을 제공하고 소감 작성으로 연결합니다.

Given:
- 완독된 책이 존재합니다.

When:
- 완독 축하 화면이 표시됩니다.

Then:
- 요약 종료일은 `todayProvider.today()`를 사용합니다.
- 시작일이 종료일보다 늦으면 시작일을 종료일로 보정해 역전 표기를 막습니다.
- 읽은 일수는 `pagesRead > 0` 기록 수를 사용합니다.
- 소감 작성 버튼으로 다음 화면으로 이동합니다.

엣지/오류 처리:
- 페이지/일수 계산은 실패 시 안전한 기본값으로 폴백합니다.

관찰 가능 기준:
- 00:00~03:59 구간에서 04:00 경계 정책 기준 날짜가 반영되는지 확인.
- 시작일 역전 데이터에서 보정 표기 확인.

## F-09 완독 소감 저장 및 수정

기능 목적:
- 완독 소감을 저장/수정합니다.

Given:
- 사용자가 소감 입력 화면에 진입했습니다.
- 완독 직후 경로(축하 화면) 또는 완독 리스트의 소감 수정 경로에서 진입합니다.

When:
- 사용자가 저장 버튼 또는 이전 버튼을 누릅니다.

Then:
- 완독 상태 확정(완료일/알림 해제 포함)은 F-07 완독 기록 분기에서 먼저 수행됩니다.
- F-09 저장은 `updateCompletionReview` 경로로 소감 텍스트를 갱신합니다.
- 저장 후 홈 루트로 복귀합니다.
- 완독 직후 경로에서 이전 버튼을 누르면 완독 축하 화면으로 한 단계 복귀합니다.
- 완독 리스트 소감 수정 경로에서 이전 버튼을 누르면 한 단계 뒤로 복귀합니다.

엣지/오류 처리:
- 입력값은 trim 후 빈 문자열이면 저장을 차단합니다.
- 공백/개행만 입력된 문자열은 저장하지 않습니다.
- 앱 재실행 후에는 이미 확정된 완독 상태가 유지되며, 소감은 빈 값일 수 있습니다.

관찰 가능 기준:
- 완독 직후 경로/소감 수정 경로 저장 결과.
- 완독 직후 경로 이전 버튼은 완독 축하로 한 단계 복귀, 소감 수정 경로 이전 버튼은 한 단계 복귀.
- 공백/개행-only 입력 차단 여부.
- 앱 재실행 후 완독 리스트 유지 여부.

## F-10 기존 책의 목표기간 수정

기능 목적:
- 읽는 책의 기간/쉬는날을 다시 설정해 남은 구간 스케줄을 재계산합니다.

Given:
- 읽는 책 상세에서 기간 수정 화면에 진입했습니다.

When:
- 기간/쉬는날을 변경하고 저장합니다.

Then:
- 남은 일정이 새 기간 기준으로 재분배됩니다.
- 시작일이 미래로 이동하면 전체 스케줄 재생성 경로를 사용합니다.
- 오늘 이미 읽은 기록이 있으면 다음날부터 재분배합니다.
- 재분배 기준일(today)은 현재 기기 time zone + 04:00 경계 기준입니다.
- 설정일 비교/정리는 `FGUserSetting.startDateKey/targetEndDateKey/excludedReadingDayKeys` 기준으로 수행됩니다.

엣지/오류 처리:
- 변경 범위 밖 기록/쉬는날은 정리 대상입니다.

관찰 가능 기준:
- 수정 전후 일일 목표 변화.
- 오늘 기록 유무에 따른 재분배 시작일 차이.

## F-11 앱 재진입 자동 재분배

기능 목적:
- 앱 재진입 시 미기록 구간이 있으면 오늘 기준으로 남은 목표를 재분배합니다.

Given:
- 읽는 책이 존재하고 앱이 홈으로 재진입합니다.

When:
- 홈 초기화 시 재분배 로직이 실행됩니다.

Then:
- 오늘 기준으로 남은 기간 목표를 다시 나눕니다.
- 시작일이 오늘 이후인 책은 시작 전으로 간주합니다.
- 여기서 today는 현재 기기 time zone + 04:00 경계 기준입니다.

엣지/오류 처리:
- 오늘 이미 읽은 경우 재분배를 생략합니다.
- 오늘이 목표 종료일 이후면 종료일 초과 오류로 분기합니다.

관찰 가능 기준:
- 앱 재진입 직후 스케줄 재계산 여부.
- 종료일 초과 시 미완독 종료 화면 진입 여부.

## F-12 미완독 종료 플로우

기능 목적:
- 목표기간이 지난 책에 대해 기간 연장 또는 종료를 선택하게 합니다.

Given:
- 종료일 초과 책으로 미완독 종료 화면에 진입했습니다.

When:
- 사용자가 닫기/뒤로/기간 연장을 선택합니다.

Then:
- 닫기 또는 뒤로: `completeBook(id:review:)` 경로로 완료 처리 후 홈으로 복귀합니다.
- 기간 연장: 기간 수정 화면으로 이동합니다.

엣지/오류 처리:
- 종료 처리 시 소감은 빈 문자열로 저장됩니다.
- 종료 처리에는 완료 상태 저장 + 완료일/시작일 보정 + 알림 해제가 포함됩니다.
- 완료일은 목표 종료일이 아니라 실행 시점 `todayProvider.today()`로 저장됩니다.

관찰 가능 기준:
- 닫기/뒤로 시 읽는 책 목록에서 제거 여부.
- 닫기/뒤로 후 알림 해제 반영 여부.
- 기간 연장 버튼의 라우팅 확인.

## F-13 알림 설정 화면

기능 목적:
- 앱 알림 ON/OFF, 리마인드 시간, 시스템 권한 상태를 한 화면에서 제어합니다.

Given:
- 알림 설정 화면 진입 시 현재 시스템 권한과 저장된 앱 설정을 조회할 수 있습니다.

When:
- 사용자가 토글 또는 시간 피커를 변경합니다.

Then:
- 시스템 권한과 앱 내부 토글이 모두 켜진 경우에만 알림 발송 대상이 됩니다.
- 시간은 04:00~23:55 범위, 5분 간격으로 선택됩니다.
- 앱이 설정 앱에서 복귀하면 권한 상태를 재동기화합니다.

엣지/오류 처리:
- 앱 토글이 OFF 상태면 시간 변경 시 시간만 저장하고 알림 재등록은 수행하지 않습니다.
- 시스템 권한 OFF 배너의 버튼은 설정 앱 이동을 수행합니다.

관찰 가능 기준:
- 토글 변경 시 알림 clear/setup 분기.
- OFF 상태 시간 변경 시 알림 업데이트 호출이 없는지 확인.

## F-14 알림 스케줄 계산 및 발송

기능 목적:
- 등록/기록/설정 변경에 맞춰 아침/야간 알림의 날짜와 문구를 계산해 발송합니다.

Given:
- 읽는 책의 진행 상태와 알림 설정 시간이 존재합니다.

When:
- 알림 스케줄링 또는 재스케줄링이 수행됩니다.

Then:
- 다음 읽기일을 찾아 아침/야간 알림 날짜로 사용합니다.
- 아침 제목은 다음 목표 페이지를 포함할 수 있습니다.
- 식별자는 `{bookId}-morning`, `{bookId}-night` 규칙을 사용합니다.

엣지/오류 처리:
- 다음 읽기일이 없으면 요청을 만들지 않습니다.
- `updateNotification`은 기존 식별자 요청 삭제 후 재등록 전 `canSendNotifications()`를 다시 검증합니다.
- 야간 알림 시간은 `(24, 0)` 고정입니다.
- 다음 읽기일 탐색 하한은 `max(lastReadDate ?? today, today)`입니다.
- 다음 목표 페이지 계산은 `records 기반 max pagesRead + 1` 우선, 없으면 `lastReadPage + 1`로 폴백하며 범위를 clamp 합니다.

관찰 가능 기준:
- 기록 후 알림 날짜/문구 변경 여부.
- 권한/앱토글 OFF 상태에서 재등록 차단 여부.

## F-15 읽는 책/완독 책 목록 및 삭제

기능 목적:
- 읽는 책/완독 책을 분리 표시하고 삭제를 제공합니다.

Given:
- 홈에서 읽는 책 카드와 완독 리스트가 표시됩니다.

When:
- 사용자가 읽는 책 또는 완독 책 삭제를 확정합니다.

Then:
- SwiftData에서 해당 책을 삭제하고 저장합니다.
- 삭제 후 선택 인덱스를 보정합니다.
- 삭제 확인 문구는 복구 불가 메시지를 제공합니다.

엣지/오류 처리:
- 저장 실패 시 오류 로그를 출력합니다.
- 삭제 후 남은 읽는 책이 있으면 해당 책 기준으로 알림을 재설정하고, 없으면 전체 알림을 해제합니다.

관찰 가능 기준:
- 읽는 책 삭제 후 캐러셀 인덱스 보정.
- 삭제 후 남은 책 있음/없음 분기별 알림 처리 확인.

## F-16 전체 캘린더/주간 진행률 표시

기능 목적:
- 주간/월간 단위로 독서 기록의 진행 상태를 시각화합니다.

Given:
- 읽는 책의 일별 기록과 목표 데이터가 존재합니다.

When:
- 사용자가 홈의 주간 카드 또는 전체 캘린더 화면을 확인합니다.

Then:
- 날짜 셀 상태를 완독일/오늘/달성/미래/미달로 구분해 표시합니다.
- 오늘 기준 표시는 04:00 경계 보정 날짜와 일치해야 합니다.
- 기록 조회 키 포맷은 `ReadingDateKey` 기반 경로로 일관되게 해석됩니다.
- 날짜 키 해석 기준 타임존은 `Calendar.app`(현재 기기 time zone)입니다.

엣지/오류 처리:
- 기록이 없는 날짜는 기본 상태로 렌더링합니다.

관찰 가능 기준:
- 동일 데이터에서 주간/월간 화면 상태 일치 여부.
- 날짜 키 파싱/비교가 로케일 영향 없이 일관되는지 확인.

## F-17 저장소 및 도메인 서비스 경계

기능 목적:
- 저장소와 도메인 서비스를 통해 등록/조회/기록/삭제/완독 규칙을 실행합니다.

Given:
- `SwiftDataBookRepo`와 도메인 UseCase 경계가 조립되어 있습니다.

When:
- 화면이 등록/조회/기록/삭제/완독 액션을 호출합니다.

Then:
- CRUD와 부분 업데이트(설정/진행상태/완독상태)를 분리해 수행합니다.
- 서비스는 계산기(`ReadingScheduleCalculator`)와 저장소를 조합합니다.
- 호출 계층은 `RepoError`, `RecordReadingResult` 기반으로 분기합니다.

엣지/오류 처리:
- `fetch`/`get` 조회 경계에서 읽기 기록 키 1회 마이그레이션을 허용하며, 필요 시 write-back(save)이 발생할 수 있습니다.
- `fetch`/`get` 조회 경계에서 설정일 key(`startDateKey`, `targetEndDateKey`, `nonReadingDayKeys`) 1회 backfill을 허용하며, 필요 시 write-back(save)이 발생할 수 있습니다.
- 마이그레이션 완료 키가 기록된 이후에는 재실행하지 않습니다.
- 설정일 `Date` 레거시 필드 제거는 별도 스키마 마이그레이션 작업으로 분리합니다.

관찰 가능 기준:
- 첫 조회 시 키 마이그레이션/완료 키 기록 여부.
- 이후 조회에서 재마이그레이션이 발생하지 않는지 확인.
