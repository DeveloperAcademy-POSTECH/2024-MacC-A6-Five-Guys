# Main 기준 피처 베이스라인

이 문서는 `main` 브랜치의 사용자 관찰 기능을 기준 계약으로 고정하기 위한 문서입니다.  
현재 리팩토링 브랜치의 차이는 이 파일이 아니라 `docs/product/current-diff-from-main.md`에만 기록합니다.

기준 커밋: `8f590c55c163266580bfe425477c76849a88feac`  
기준 범위: `FiveGuyes/FiveGuyes/Sources/**`

## F-01 앱 시작 및 전역 네비게이션

앱 시작 시 SwiftData `ModelContainer`를 초기화하고, `NavigationRootView`에서 홈 화면을 루트로 띄웁니다. 앱 델리게이트에서는 Firebase 초기화와 ATT 권한 요청을 수행합니다.

이 피처에서 중요한 고려사항은 다음입니다.  
첫째, 컨테이너 생성 실패는 앱 기동 실패로 간주됩니다.  
둘째, 네비게이션은 `NavigationCoordinator` 단일 상태(`paths`, `viewReloadTrigger`)로 통제합니다.  
셋째, 화면 전환 타입(`Screens`)이 앱 전체 이동 계약입니다.

## F-02 홈 대시보드

홈은 읽는 책/완독 책 상태에 따라 제목, 메인 카드, 액션 버튼을 다르게 보여줍니다. 읽는 책이 있으면 캐러셀과 점 인디케이터를 보여주고, 없으면 빈 상태 메시지를 노출합니다.

고려사항은 다음입니다.  
첫째, 선택된 책 인덱스(`selectedBookIndex`)와 활성 ID(`activeBookID`)를 동기화해 카드 스크롤과 액션 대상을 일치시킵니다.  
둘째, 진입 시 읽는 책 전체에 대해 재분배를 시도하고 종료일 초과는 별도 플로우(미완독 종료 화면)로 분기합니다.  
셋째, 홈 진입 직후 현재 읽는 책 기준 알림을 다시 설정합니다.

## F-03 책 검색 및 선택

사용자는 알라딘 API로 책을 검색하고, 검색 결과 중 하나를 선택합니다. 선택 후 ISBN으로 총 페이지 수를 조회해 목표 입력의 종료 페이지 기본값으로 사용합니다.

고려사항은 다음입니다.  
첫째, API 키는 앱 번들에서 읽어오며 없으면 즉시 실패합니다.  
둘째, 검색 결과/상세 조회 실패는 앱 크래시 대신 오류 로그와 안전 기본값(`0` 페이지)으로 처리합니다.  
셋째, 책 미선택 상태에서는 완료 버튼을 비활성화합니다.

## F-04 완독 목표 설정 마법사

책 등록은 `검색 -> 페이지 -> 기간 -> 쉬는날 -> 완료`의 단계형 흐름으로 진행됩니다. 단계 상태는 `BookSettingPageModel`, 입력 상태는 `BookSettingInputModel`이 관리합니다.

고려사항은 다음입니다.  
첫째, 뒤로가기 시 현재 단계에 맞는 입력만 초기화합니다.  
둘째, 단계별 진행바를 통해 현재 위치를 명확히 보여줍니다.  
셋째, 기간/휴일 단계는 공용 캘린더 선택 모델을 재사용합니다.

## F-05 기간/쉬는날 선택

캘린더에서 시작일과 종료일을 선택한 뒤, 확정 모드에서 쉬는날을 토글합니다. 선택된 기간을 기반으로 예상 일일 페이지 수를 실시간 표시합니다.

고려사항은 다음입니다.  
첫째, 과거 날짜는 선택 불가입니다.  
둘째, 시작일/종료일은 쉬는날로 지정할 수 없습니다.  
셋째, 기간 재선택 시 범위를 벗어난 기존 쉬는날은 제거합니다.  
넷째, 날짜 비교는 `Calendar.app` 기준의 day-start 정규화 값을 사용합니다.

## F-06 등록 완료 및 책 생성

최종 확인 화면에서 추천 일일 분량과 기간을 보여준 뒤 실제 책 데이터를 저장합니다. 저장 시 초기 읽기 스케줄을 생성하고 알림을 설정합니다.

고려사항은 다음입니다.  
첫째, 초기 진행 페이지는 시작 페이지 직전(`startPage - 1`)에서 시작합니다.  
둘째, 초기 스케줄 계산은 종료일/쉬는날/페이지 범위를 모두 반영합니다.  
셋째, 저장 직후 알림을 등록해 첫날부터 리마인드가 동작하도록 보장합니다.

## F-07 일일 독서 기록 입력

사용자가 오늘까지 읽은 누적 페이지를 입력하면 기록을 저장하고, 필요하면 남은 일정을 재분배합니다. 결과는 일반 기록/완독/종료일 연장/초과입력으로 분기됩니다.

고려사항은 다음입니다.  
첫째, 목표 종료 페이지 초과 입력은 경고 알림으로 재확인합니다.  
둘째, 마지막 날 미달 입력은 종료일을 자동으로 하루 연장한 뒤 재분배합니다.  
셋째, 목표와 실제가 다르면 미래 날짜 목표를 다시 계산합니다.  
넷째, 기록 후 알림을 재설정해 다음 알림 내용과 날짜가 최신 상태를 반영하도록 합니다.

## F-08 완독 축하 요약

완독 직후 축하 화면에서 기간/일수/일일 평균 읽기량 요약을 보여주고, 소감 작성 화면으로 이동시킵니다.

고려사항은 다음입니다.  
첫째, 시작일이 완료 표시일보다 늦은 경우를 방어해 요약 날짜 역전을 막습니다.  
둘째, 읽은 일수는 실제 읽은 기록(`pagesRead > 0`) 기준입니다.  
셋째, 카드/문구는 완독의 성취감을 강조하는 제품 피드백 역할을 수행합니다.

## F-09 완독 소감 저장 및 수정

소감 화면은 신규 저장 모드와 수정 모드를 분리합니다. 신규 저장은 완독 상태를 확정하고, 수정은 소감 텍스트만 바꿉니다.

고려사항은 다음입니다.  
첫째, 비어 있는 문자열은 저장하지 않습니다.  
둘째, 신규 저장 시 완료일을 반영하면서 시작일-종료일 역전도 함께 보정합니다.  
셋째, 저장 완료 후 홈 루트로 복귀해 사용자가 즉시 결과를 확인할 수 있게 합니다.

## F-10 기존 책의 목표기간 수정

이미 읽는 책에 대해 기간/쉬는날을 다시 선택하면 남은 구간 스케줄을 재계산합니다.

고려사항은 다음입니다.  
첫째, 시작일이 미래로 바뀌면 전체 스케줄 재생성 경로를 탑니다.  
둘째, 이미 오늘 기록한 경우에는 다음날부터 재분배합니다.  
셋째, 변경된 기간 밖 기록 및 쉬는날 기록은 정리(clean-up) 대상입니다.

## F-11 앱 재진입 자동 재분배

앱에 다시 들어왔을 때 미기록 구간이 있으면 오늘 기준으로 남은 목표를 다시 나눕니다.

고려사항은 다음입니다.  
첫째, 오늘 이미 읽은 경우 재분배를 건너뜁니다.  
둘째, 시작일이 오늘 이후인 책은 아직 시작 전으로 간주합니다.  
셋째, 오늘이 목표 종료일 이후면 오류로 분기해 미완독 종료 플로우를 유도합니다.

## F-12 미완독 종료 플로우

목표기간이 지난 책에 대해 사용자는 기간 연장 또는 종료를 선택할 수 있습니다.

고려사항은 다음입니다.  
첫째, 종료 선택 시 완료 상태를 저장해 읽는 책 목록에서 제거되도록 합니다.  
둘째, 연장 선택 시 기간 수정 화면으로 즉시 이동합니다.  
셋째, 뒤로가기 동작도 종료 처리와 동일한 안전 상태를 유지해야 합니다.

## F-13 알림 설정 화면

알림 전체 on/off, 리마인드 시각, 시스템 권한 상태를 한 화면에서 제어합니다.

고려사항은 다음입니다.  
첫째, 시스템 권한과 앱 내부 토글이 모두 켜져야 실제 알림이 발송됩니다.  
둘째, 리마인드 시각은 04:00~23:55, 5분 단위로 제한합니다.  
셋째, 앱이 백그라운드에서 설정 앱을 다녀온 경우 권한 상태를 다시 동기화합니다.

## F-14 알림 스케줄 계산 및 발송

등록/기록/설정 변경 시 아침/야간 알림을 다시 구성합니다. 알림 날짜는 다음 읽기일, 문구는 다음 목표 페이지 기반으로 생성됩니다.

고려사항은 다음입니다.  
첫째, 다음 읽기일이 없는 경우는 요청을 만들지 않습니다.  
둘째, 알림 식별자 규칙(`{bookId}-morning`, `{bookId}-night`)으로 중복을 제어합니다.  
셋째, 시간 변경 시 전체 재등록이 아닌 해당 식별자 알림 갱신 경로를 제공합니다.

## F-15 읽는 책/완독 책 목록 및 삭제

읽는 책과 완독 책을 분리 조회해 홈에 표시하고, 각 영역에서 삭제를 지원합니다.

고려사항은 다음입니다.  
첫째, 삭제 후 선택 인덱스를 안전하게 재조정해 out-of-range를 방지합니다.  
둘째, SwiftData 저장 실패를 로깅하고 앱 비정상 종료로 이어지지 않도록 합니다.  
셋째, 삭제 확인 문구는 복구 불가를 명확히 전달합니다.

## F-16 전체 캘린더/주간 진행률 표시

사용자는 주간 진행률과 월 단위 전체 캘린더에서 기록 상태를 시각적으로 확인할 수 있습니다.

고려사항은 다음입니다.  
첫째, 날짜 셀 상태는 완독일/오늘/달성/미래/미달을 구분합니다.  
둘째, 오늘 기준 표시는 04:00 경계 보정 날짜와 일치해야 합니다.  
셋째, 기록 조회 키 포맷은 전 화면에서 동일해야 UI 불일치가 발생하지 않습니다.

## F-17 저장소 및 도메인 서비스 경계

`BookRepository`와 `DefaultBookManagementService`는 등록/조회/기록/삭제/완독의 단일 비즈니스 진입점을 제공합니다.

고려사항은 다음입니다.  
첫째, CRUD와 부분 업데이트(설정/진행상태/완독상태)를 분리해 변경 범위를 최소화합니다.  
둘째, 서비스는 계산기(`ReadingScheduleCalculatorV2`)와 저장소를 조합해 도메인 규칙을 실행합니다.  
셋째, 에러 타입(`RepositoryError`, `RecordReadingResult`)은 호출 계층이 분기 처리할 수 있는 계약입니다.

## 문서 운영 메모

리팩토링/현재 상태와의 비교는 반드시 `docs/product/current-diff-from-main.md`에만 추가합니다.
