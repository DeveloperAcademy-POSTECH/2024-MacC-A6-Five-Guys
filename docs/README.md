# docs

한입독서의 프로젝트 문서를 두는 폴더입니다. 문서는 성격에 따라 하위 폴더로 나눕니다.

| 경로 | 성격 | 고치는 법 |
|---|---|---|
| `features/` | 현재 기준(SoT). 앱이 지금 어떻게 동작해야 하는가. 기능 하나에 파일 하나 | 동작이 바뀌면 코드와 같은 PR에서 고칩니다. 코드가 문서와 다르면 코드의 버그로 보고 이슈로 남깁니다 |
| `decisions/` | 결정 기록(ADR). 그때 무엇을 왜 정했는가 | 이미 쓴 내용은 고치지 않습니다. 결정이 바뀌면 새 ADR을 추가하고 예전 ADR에 대체 표시만 합니다 |

구조의 현재 기준은 루트의 `ARCHITECTURE.md`입니다.

## 기능 문서 형식 (`features/`)

- **용어**: 문서에서 쓰는 말의 뜻을 먼저 정합니다.
- **사용자 시나리오**(S1, S2, …): 사람이 의도한 흐름을 확인하는 용도입니다.
- **요구사항**(ID 부여): 구현과 테스트를 검증하는 기준입니다. 공통 규칙과 종류별 규칙이 있으면 장을 나눕니다.

진행 상황, 검증 방법, 이슈, 후속 과제는 넣지 않습니다.

## 예전 기능 설명

`product/`의 기능 설명은 예전 문서이며 기준이 아닙니다. 관련 기능을 작업할 때 내용을 `features/`로 옮기고, 같은 커밋에서 예전 문서의 해당 설명을 지웁니다. 아직 옮기지 않은 기능은 예전 문서를 참고할 수 있지만, 코드와 다르면 코드를 확인하고 사용자에게 묻습니다.
