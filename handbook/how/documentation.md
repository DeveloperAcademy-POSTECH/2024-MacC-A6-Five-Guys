# Documentation

한입독서의 문서는 레포 루트의 세 폴더에 성격별로 나눠 둔다. 진입점은 루트 `AGENTS.md`이고, 소스 폴더(`FiveGuyes/FiveGuyes/Sources`)에는 문서를 두지 않는다.

| 경로 | 성격 | 고치는 법 |
|---|---|---|
| `handbook/` | 팀 지식. 이 코드를 몰라도 성립하는 환경·도구(`where/`)와 프로세스·컨벤션(`how/`) | 작업 방식이 바뀌면 고친다 |
| `services/` | 이 코드에 대한 지식. 여러 서비스에 공통인 구조는 `_common/`, 기능별 지식은 `services/<서비스>/` | 구조나 동작이 바뀌면 코드와 같은 PR에서 고친다 |
| `history/` | 기록. `decisions/`에 ADR(그때 무엇을 왜 정했는가), `backlog.md`에 문서와 다른 코드 목록 | 결정이 바뀌면 새 ADR을 추가하고 예전 ADR에 대체 표시를 한다. backlog는 `backlog.md` 안의 규칙을 따른다 |

`services/`는 앱 기능과 구조에 대한 지식을 모은 곳이다.

문서 경로는 레포 루트 기준으로 쓴다.

## 기능 명세 형식 (`spec.md`)

앱이 어떻게 동작해야 하는지의 기준(SoT)은 `services/<서비스>/spec.md`에 둔다.

코드가 명세와 다르면 코드의 버그로 보고 `history/backlog.md`에 적는다.

- **용어**: 문서에서 쓰는 말의 뜻을 먼저 정한다.
- **사용자 시나리오**(S1, S2, …): 사람이 의도한 흐름을 확인하는 용도다.
- **요구사항**(ID 부여): 구현과 테스트를 검증하는 기준이다. 공통 규칙과 종류별 규칙이 있으면 장을 나눈다.

진행 상황, 검증 방법, 이슈, 후속 과제는 넣지 않는다.
